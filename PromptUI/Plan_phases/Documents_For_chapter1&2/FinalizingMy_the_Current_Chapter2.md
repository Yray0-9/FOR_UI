# METHODOLOGY

This chapter presents the methodology used in the development of **SafeBooks: A Secure Financial Records Monitoring System with Tax Compliance Tracking and Predictive Risk Analytics**. It outlines the structured procedures followed in planning, analyzing, designing, implementing, and maintaining the system to ensure that it effectively supports bookkeeping professionals in managing client financial records and monitoring tax compliance.  

The study adopted the **Modified Waterfall Model** under the **System Development Life Cycle (SDLC)** due to its systematic and sequential approach, which is appropriate for projects with clearly defined requirements. The model aligns with the **PADIM framework**, consisting of **Planning, Analysis, Design, Implementation, and Maintenance**, where each phase is completed before proceeding to the next. This approach ensures an organized development process, allowing the system to be built accurately based on identified requirements and evaluated for functionality and effectiveness.

# System Planning

The system planning phase focuses on how the researchers conceptualized and organized the development of **SafeBooks: A Secure Financial Records Monitoring System with Tax Compliance Tracking and Predictive Risk Analytics**. This phase involves identifying the existing challenges faced by bookkeeping professionals, defining the scope and objectives of the system, and establishing a structured plan for its development. It ensures that all necessary resources, tasks, and responsibilities are clearly defined before proceeding to the subsequent phases of the system development process.  

The idea of the project originated from the observed reliance of home-based bookkeepers on manual and paper-based methods in managing client financial records and monitoring tax compliance. These practices result in inefficiencies in record retrieval, lack of data organization, and absence of analytical support for decision-making. In response to these challenges, the researchers proposed a web-based system that centralizes financial records, enables TIN-based search, and incorporates analytics and risk classification features. To ensure a systematic and organized development process, the project follows the Modified Waterfall Model, which guides the progression of tasks from planning to maintenance.

# Work Breakdown Structure (WBS)

The Work Breakdown Structure (WBS) for this study follows the Modified Waterfall Model introduced in the chapter opening. The WBS decomposes the project into sequential, review-gated phases so that each phase produces concrete deliverables before the next phase begins. The phases are: **Planning**, **Requirements Analysis**, **System Design**, **Development / Implementation**, **Testing & Deployment**, and **Maintenance**. Each phase below lists only the essential activities and deliverables.

1. Planning
- 1.1 Identify project problem and objectives
- 1.2 Define project scope and limitations
- 1.3 Identify target users and stakeholders
- 1.4 Form project team and assign roles
- 1.5 Prepare project development plan and schedule

2. Requirements Analysis
- 2.1 Gather detailed system requirements
- 2.2 Analyze current manual recordkeeping process and data needs
- 2.3 Identify functional requirements (TIN search, client profiles, monthly records, reporting)
- 2.4 Identify non-functional requirements (security, usability, performance)
- 2.5 Define acceptance criteria and validation rules

3. System Design
- 3.1 Design overall system architecture
- 3.2 Design database schema and ERD
- 3.3 Design user interface (dashboard, record form, reports)
- 3.4 Define system modules and interfaces
- 3.5 Design data flow and validation rules

4. Development / Implementation
- 4.1 Implement database schema and migrations
- 4.2 Develop backend modules and services
- 4.3 Build views, templates, and UI components
- 4.4 Implement TIN-based search and data retrieval
- 4.5 Implement analytics processing and rule-based classification
- 4.6 Integrate components and perform module-level testing

5. Testing & Deployment
- 5.1 Conduct automated unit and integration tests
- 5.2 Perform user acceptance testing (UAT) with stakeholders
- 5.3 Triage and fix identified bugs
- 5.4 Prepare deployment settings and run migrations
- 5.5 Deploy system and verify production readiness

6. Maintenance
- 6.1 Monitor system performance and logs
- 6.2 Fix reported errors and apply patches
- 6.3 Update system features based on feedback
- 6.4 Maintain data integrity, backups, and security
- 6.5 Update user documentation and release notes

# System Architecture

The SafeBooks system follows a web-based client-server architecture, where home-based bookkeepers interact with the system through a web browser, while data processing, storage, and system functionalities are managed on a centralized server. This architecture enables centralized management of client financial records, secure data handling, and efficient access to system features such as financial tracking, analytics, and reporting.  

The system consists of several key components. The primary users are bookkeepers who access the system to manage client profiles, encode financial records, monitor tax compliance, and generate reports. The user interface serves as the front-end component, providing forms, dashboards, and report views that allow users to interact with the system. The application server handles the core system processes, including data validation, record management, TIN-based search functionality, financial analytics processing, and rule-based risk classification. The database serves as the storage component, maintaining client profiles, financial records, tax compliance data, and generated analytical results. Additionally, the system incorporates a secure authentication mechanism to ensure that only authorized users can access sensitive financial and client information.  

The system process begins when the user logs into the platform using valid credentials. The user then inputs or updates client profiles and monthly financial records through the interface. These inputs are validated and stored in the database. The application server processes the stored data to generate financial summaries, perform trend analysis, and produce forecasting results based on recorded patterns. The system then applies predefined rules to classify each client business into corresponding risk levels. All processed information, including financial trends, compliance status, and risk classification, is displayed through the dashboard and can be generated as structured reports. This architecture ensures a centralized, secure, and organized approach to managing financial records and supporting data-driven advisory decisions.

# Functional and Non-Functional Requirements

The SafeBooks system provides essential functionalities that support bookkeepers in managing client financial records, monitoring tax compliance, and generating analytical insights. The system enables centralized data management, allowing users to store, retrieve, and process financial and compliance data efficiently. It also incorporates analytical features such as financial trend analysis, forecasting, and rule-based risk classification to support informed decision-making. These functionalities are designed to address the limitations of manual recordkeeping and improve the overall efficiency of bookkeeping operations.  

In terms of quality attributes, the system is designed to ensure usability, security, reliability, and performance. It provides a user-friendly interface for easy navigation and data entry, while ensuring that sensitive financial and client information is protected through secure authentication. The system is also designed to operate efficiently within standard computing environments and maintain consistent performance during use. Additionally, it supports maintainability, allowing updates and improvements to be implemented as needed.  

---

## Functional Requirements

1. The system shall allow users to create, update, and manage client business profiles, including BIR-related information.  
2. The system shall record and store monthly financial and tax compliance data for each client business.  
3. The system shall provide a TIN-based search function to quickly locate specific client records.  
4. The system shall validate user input to ensure completeness and consistency of financial data.  
5. The system shall process stored financial data to generate descriptive summaries of financial trends.  
6. The system shall perform predictive forecasting based on recorded financial patterns.  
7. The system shall classify client businesses into Low, Medium, or High Risk using predefined rules.  
8. The system shall display financial summaries, compliance status, and risk classifications through a dashboard.  
9. The system shall generate organized reports combining financial data, analytics, and compliance information.  
10. The system shall implement user authentication to restrict access to authorized users only.  

---

## Non-Functional Requirements

1. The system shall provide a user-friendly interface that is easy to navigate and understand.  
2. The system shall ensure data security by protecting sensitive client and financial information through authentication mechanisms.  
3. The system shall maintain data accuracy and integrity during storage and processing.  
4. The system shall perform system operations efficiently with minimal delay in data processing and retrieval.  
5. The system shall be compatible with standard web browsers and typical desktop or laptop devices.  
6. The system shall be reliable and capable of consistent operation during regular use.  
7. The system shall be maintainable, allowing updates and modifications without affecting overall system functionality.  
8. The system shall handle multiple client records without significant performance degradation.

# Entity Relationship Diagram (ERD)

The Entity-Relationship Diagram (ERD) illustrates the database structure of the SafeBooks system, showing the relationships between key entities involved in managing client financial records, tax compliance data, and analytical outputs. It represents how data is organized, stored, and interconnected within the system to support efficient bookkeeping operations.  

The main entities in the system include Bookkeeper, Admin, Client, Financial_Record, Period, Risk_Classification, and Report. The Bookkeeper entity manages multiple client businesses, while the Admin entity oversees and manages user accounts within the system. Each Client represents a business profile containing taxpayer and BIR-related information, which is linked to the assigned bookkeeper.  

The Financial_Record entity stores monthly financial and tax-related data for each client, including revenue, expenses, tax amount, and filing status. Each record is associated with a specific Period, which defines the reporting timeframe. The system processes these records to generate analytical outputs stored in the Risk_Classification entity, which includes risk levels and advisory notes based on financial trends. Additionally, the Report entity stores generated reports that summarize financial data, analytics, and compliance information for each client.
